Tally Design System

The visual and interaction system for JH Media Group's time tracking, profitability, and invoicing tool. Every token on this page is live: the guide imports the same tokens.css that ships in the app, so what you see is what renders in production. Click any swatch or scale row to copy its token.

Principles

Seven rules. When two designs are both defensible, these break the tie.

1. Logging time must cost nothing. Every second of friction is multiplied by eleven people times two hundred and fifty days. The timer is one keystroke from anywhere.
2. Never lose a keystroke. Autosave, optimistic writes, an offline-tolerant timer, and a visible saved state. The user should never wonder whether something stuck.
3. Keyboard-first, mouse-complete. A command palette and a documented shortcut map. Nothing is keyboard-only, nothing is mouse-only.
4. Show the number, then the breakdown. Lead with the figure that matters and let people drill down. Never the reverse.
5. Destructive actions are reversible. Archive over delete. Undo on anything that removes data. Typed confirmation for the rest.
6. Money is exact. Integer minor units, snapshotted rates, and tabular figures so columns line up and a ticking timer never makes a row jitter.
7. Colour means something. Chrome is neutral. Colour is reserved for state, and every use of it is paired with a word or an icon.

Theming

Three states, one definition per token. The root element carries no attribute by default and follows the OS; an explicit choice stamps data-theme="light" or data-theme="dark".

:root                      { color-scheme: light dark; }   /* follows the OS */
:root[data-theme="light"]  { color-scheme: light; }
:root[data-theme="dark"]   { color-scheme: dark;  }

--surface: light-dark(#FFFFFF, #111113);
Why
CSS light-dark() means each colour is defined exactly once. There is no media query and no second dark block to keep in sync, which removes the most common theming bug: a token updated in one block and forgotten in the other. Setting the attribute is the entire implementation. Browser floor is Chrome 123, Safari 17.5, Firefox 120, all shipped in 2024.
!
Never define a colour only inside a @media or [data-theme] block. Every token lives on bare :root. If you find yourself writing a dark override, you are working against the system.

Flip the toggle in the top right. Everything below re-renders from the same variables, including the charts.

Motion

Fast is the default. Only transform and opacity are ever animated; never height, never top.

!
Reduced motion is honoured at the token layer. prefers-reduced-motion collapses all three durations to 1ms and stops the timer pulse, leaving the dot solid. A component that animates outside the token system is a bug.

Icons

Lucide, 1.5px stroke, currentColor only. 16px in dense chrome, 20px in navigation. Every icon-only control carries an aria-label and a tooltip.

!
Never a coloured icon except inside a status badge, where it inherits the badge's foreground. An icon that carries its own colour competes with the four reserved meanings.

The no-shift rule

Clicking anything in a table must never move the table. A user ticking checkboxes down a column is aiming at a target. If the first tick pushes the grid down by one row, the second tick lands on the wrong record, and on a forty-row bulk edit that is not a risk, it is a certainty.

How a table normally shiftsWhat we do instead
Selection adds a border to the rowSelection is a background plus an inset shadow. Inset paints; it does not reflow.
Row actions appear on hoverActions always occupy their space and toggle opacity. Never display, never a width change.
A menu expands inline and pushes rows downMenus are portalled overlays, positioned above the grid.
A bulk action bar appears when you selectThe action row is always in the layout at --action-row-h. Only its contents change.
An action form grows the toolbarActions that fit one row render inline; anything larger opens a modal, which is an overlay.
The grid resizes as rows loadThe page owns the grid's height. The grid scrolls inside it.

The action row has three states layered on top of each other and cross-faded. Because all three are absolutely positioned inside a fixed-height container, the height cannot change even mid-transition.

browse   filters, column picker, export          nothing selected
select   "N selected", bulk actions, clear       rows ticked
act      the chosen action's inline form         action chosen

Escape returns act -> select.  Clear returns select -> browse.

✓ Do

Reserve the space up front. An empty 48px row that never moves costs less than a bar that appears and displaces everything the user was aiming at.

× Don't

Float the bar over the bottom of the viewport. It shifts nothing, but it covers the last rows of the table, which are exactly the rows someone scrolled down to select.

!
This applies to every table in the product, not just grids. Any list with a checkbox, an Actions menu, or a hover-revealed control follows the same rule. The test is mechanical: screenshot the table, interact with it, screenshot again, and diff. Any vertical movement outside the action row's own contents is a bug.

The Community boundary

We are on the MIT Community edition. Three things the product needs are Enterprise-only, so each has a Community pattern.

Enterprise featureWhat we do instead
Row groupingGroup headers are full-width rows injected into the flat row array, in server order
AggregationGroup and grand totals are computed server-side and carried on the row
Master / detailDetail panels are full-width rows injected on expand
Columns tool panelOur own Columns popover, which the PRD already specified
Set filterFilter chips in the page toolbar, which read better than in-header filters
Context menuThe row Actions menu
Excel exportCSV client-side; XLSX from the server export job
Why
Server-computed totals are the better design regardless of licensing. Client-side aggregation would re-derive figures in the browser using different rounding than the server applies, and would happily sum a column the current user is not permitted to see. Totals that come from the same SQL as the reports cannot drift from them.

Rules

Numeric columns are right-aligned with tabular figures. Without this, comparing a column of amounts by eye is guesswork.
Hairline row separators, no vertical rules. Verticals turn a table into a spreadsheet and make scanning a row harder. The week grid is the deliberate exception.
No zebra striping. Alternating fills fight the hover state, and hover is how a row reveals its actions.
There is no centred column. Text left, numbers right.
A row click opens the record; only the checkbox selects. Nothing gets selected by accident on the way to a detail page.
The grand total is a pinned bottom row that never scrolls away and is never sorted into the body.
A paginated total is labelled "Total for all pages" and reflects the full result set. A total that silently means something narrower than it says is a reporting bug.
Empty and loading states are ours, not the grid's. AG Grid's built-in overlay is a bare centred string with nowhere to go; ours carries the action that would fill the table.
!
The grid is route-level lazy loaded and never enters the initial bundle. AG Grid is roughly 300KB gzipped against a 180KB initial-JS budget. Timesheet Day view, the invoice document, and every printed surface use plain HTML tables instead: virtualization means only visible rows exist in the DOM, which would silently truncate a printed report and would break the requirement that the invoice render identically in the app, the PDF, and the pay page.

Donut

The one circular chart in the product. It answers a single part-to-whole question with two segments and puts the answer in the middle, so it reads as a stat tile that happens to show its own proportion.

!
Two segments is the limit, and this is the only place a ring is correct. A pie is only readable when there are very few slices and the question is genuinely "what share of the whole". The breakdowns that look like pie candidates are not: a projects breakdown has eight or more categories, and people cannot compare eight angles. Those use a stacked proportional bar with a ranked legend, which answers "which is biggest" and "by how much" at a glance. If you are reaching for a third slice, you want a bar chart.

Hover and tooltips

Every chart below is interactive. Roll over it. A chart that only shows shape is half a chart; the numbers behind the shape have to be reachable without leaving the page for a table.

The hit target is the whole column, not the mark. Chasing an 8px dot with a pointer is miserable and impossible on a trackpad at speed. Each slot gets a full-height transparent hit rectangle, so anywhere in the vertical band works.
Snap to the nearest point, never interpolate. A tooltip reading 6.4 hours for a week that recorded 6 or 7 is a fabricated number.
One tooltip per column, not per segment. A stacked bar answers "what made up this month", so the tooltip shows every segment plus the total. The exception is the donut, where two segments are two distinct answers rather than points in a series.
Arrow keys drive the same tooltip. The chart is one tab stop; left and right walk the series, Home and End jump to the ends, Escape dismisses. Data behind a hover only is data a keyboard user cannot reach.
The tooltip is inert. pointer-events: none, so it can never sit between the cursor and the mark it describes and cause a flicker loop.
It flips and clamps. Renders above the mark by default, flips below when it would leave the viewport, and clamps horizontally so it is never cut off at an edge.
The hovered mark responds. A column band tints, a bar shifts colour, a line gets its crosshair and an enlarged point. Something must confirm what the tooltip is describing.
Content
Title is the period, then one row per series with a colour swatch, the label, and a right-aligned tabular value. A footer carries the derived figure that is the actual reason someone hovered: the total on a stack, the margin on profit, over or under budget on project progress, vs average on hours. Never just repeat the axis value; the axis already said that.
!
The tooltip is in addition to the accessible name, not instead of it. Every chart keeps its role="img" and an aria-label carrying the headline, plus a table view in its overflow menu. A screen reader user gets the summary immediately and the full data on demand; neither depends on a pointer.

The current period band

Every time-series chart tints the period you are currently in, or the one selected in the period picker, and labels it. Without it a reader cannot tell whether the last bar is a real decline or simply a week that is only two days old, which is the single most common misreading of a tracking chart.

Spec
A full-height --info-bg band behind the period, drawn under the grid and marks so it never dims the data, with a small --fs-xs label at the top. A partial period also renders its bar or line segment at 60% opacity, so incomplete is visible even in a printed chart with no colour.

Accessibility

WCAG 2.2 AA on all text and UI boundaries. These are the checks that fail a build, not aspirations.

Focus ring

One ring for the whole product: 2px --focus, offset 2px. It uses :focus-visible, so clicking a button with a mouse leaves no ring behind, but every keyboard path shows one. Press Tab through the controls below to see the real thing; the second row shows the same states forced on so they can be compared side by side.

Live — press Tab A link
Forced, for comparison Checkbox
Why two
Buttons take an outline; inputs take a border swap plus a soft ring. An outline sits outside the box and does not affect layout, which is what a button needs. An input already has a visible border, so a second ring outside it reads as a double edge; swapping the border colour and adding a 3px 25%-alpha shadow keeps the ring on the control's own radius. Both are the same colour and the same weight, so they read as one system.
!
outline: none without a replacement is a bug, not a style choice. Inside the grid, AG Grid draws its own cell focus indicator; we restyle it to an inset 2px ring in the same colour rather than removing it, because focus in a grid is cellwise and the browser default would be wrong there too.

Everything else

Focus is always visible. 2px ring in --focus, offset 2px. outline: none without a replacement is a bug.
Colour is never the only channel. Status carries a word, budget health carries an icon, billable carries a label.
Every icon-only control has an accessible name and a tooltip that says the same thing.
Modals trap focus, restore it on close, and close on Escape.
Tables are real tables with a caption, header scopes, and aria-sort on sortable columns.
Charts announce their headline through role="img" and an aria-label carrying the figure, plus a table view.
Hit targets are 32px minimum in dense chrome, 44px on touch.
Reduced motion removes all non-essential motion, including the timer pulse. The dot stays solid.
Axe reports zero violations on Timesheet, Projects, Project detail, Invoices, and every report.
